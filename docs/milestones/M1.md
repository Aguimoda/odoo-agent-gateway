# Hito M1: servidor MCP de solo lectura

Versión 1.0, 2026-11-22. **Estado: hecho el 2026-11-22** (versión 0.1.0, etiqueta `m1`). Los 8 escenarios de aceptación pasan como pruebas de integración contra el Odoo de Docker.

**Lo que se aprendió al probar contra el Odoo real:** un usuario normal no puede leer `ir.model`, así que los modelos instalados se detectan preguntando `has_access` a cada modelo permitido. Además, el mensaje de un `AccessError` de Odoo incluye el nombre del registro denegado, por eso el gateway nunca lo reenvía.

## Objetivo

Un agente conectado por MCP puede consultar Odoo con 6 herramientas de lectura, y **siempre como la persona que pregunta**. Una persona que no puede ver algo en Odoo tampoco lo ve a través del agente, y eso queda demostrado con pruebas contra un Odoo real.

## Qué entra

- Cliente JSON-RPC para Odoo 18: autenticación con login y API key del usuario, y llamadas a modelos.
- Las 6 herramientas de lectura de `TOOLS.md`: `my_permissions`, `list_models`, `describe_model`, `search_records`, `read_record`, `summarize_data`.
- Servidor MCP por HTTP (streamable HTTP, sin estado, respuestas JSON) dentro de la aplicación FastAPI, junto a `/health`.
- Datos de demo reproducibles: base de datos `demo`, empresa ficticia, y dos usuarios:
  - **Ana**, de ventas, solo ve sus propios pedidos.
  - **Luis**, de dirección, ve todos.
- Pruebas unitarias (sin Odoo) y pruebas de integración contra el Odoo de Docker.

## Qué no entra (llega después)

Registro de auditoría y suite de fugas en CI (M2), RAG (M3), escrituras (M4), OAuth 2 (versión posterior), límites de uso por minuto (M2).

## Decisiones de este hito

- ADR 0005: credenciales del usuario en cada petición; el gateway no guarda ninguna.
- ADR 0006: barreras de las herramientas de lectura.
- ADR 0007: transporte MCP y protección del host.

## Escenarios de aceptación

```gherkin
Característica: Consultar Odoo como la persona que pregunta

  Antecedentes:
    Dado un Odoo con los usuarios de demo Ana (ventas, solo lo suyo) y Luis (dirección)
    Y pedidos de venta asignados a Ana y otros asignados a Luis

  Escenario: Ana solo ve sus pedidos
    Cuando Ana busca pedidos de venta con search_records
    Entonces todos los pedidos devueltos tienen a Ana como comercial
    Y ninguno de los pedidos de Luis aparece

  Escenario: Ana no puede leer un pedido de Luis aunque conozca su id
    Cuando Ana pide read_record del pedido de Luis
    Entonces la herramienta responde con un error "forbidden"
    Y no devuelve ningún dato del pedido

  Escenario: Luis ve los pedidos de ambos
    Cuando Luis busca pedidos de venta
    Entonces aparecen pedidos de Ana y de Luis

  Escenario: Una API key falsa no entra
    Cuando alguien llama con el login de Ana y una API key inventada
    Entonces la herramienta responde con un error "unauthenticated"

  Escenario: Sin credenciales no hay nada
    Cuando se llama a cualquier herramienta sin cabeceras de credenciales
    Entonces la herramienta responde con un error "unauthenticated"

  Escenario: Modelos fuera de la lista permitida
    Cuando cualquier usuario pide un modelo que no está en la lista permitida
    Entonces la herramienta responde con un error "invalid_request" sin llamar a Odoo

  Escenario: Topes de tamaño
    Cuando se piden más de 50 registros
    Entonces se devuelven como mucho 50 y la respuesta indica que hay más

  Escenario: Resumen por grupos respeta permisos
    Cuando Ana pide el total de sus pedidos agrupado por comercial
    Entonces solo aparece su propio grupo
```
