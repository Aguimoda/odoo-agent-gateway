# Hito M2: auditoría, límites y suite de fugas en CI

Versión 1.0, 2026-11-22. **Estado: hecho el 2026-11-22** (versión 0.2.0, etiqueta `m2`). Los escenarios pasan como 21 pruebas de integración contra Odoo y PostgreSQL reales. El trabajo de CI se simuló en local desde cero (clon limpio, volúmenes nuevos, `CI=true`): 21 de 21 en 89 segundos.

**Lo que se aprendió:** un trigger por fila no se dispara con `TRUNCATE`, así que la tabla de auditoría necesita además un trigger de sentencia. Y unas pruebas de integración que se saltan cuando falta su entorno darían un verde falso en el CI, así que allí fallan en vez de saltarse.

## Objetivo

Que cualquier uso del gateway deje rastro, que nadie pueda martillear Odoo a través de él, y que las pruebas de fugas de permisos se ejecuten en cada cambio contra un Odoo real, no solo en el ordenador de Daniel.

## Qué entra

1. **Registro de auditoría** en la base de datos propia del gateway (ADR 0004 y 0008). Por cada llamada a una herramienta se guardan:
   - el momento;
   - el id de la petición;
   - el login declarado y el id que confirma Odoo;
   - la herramienta y sus argumentos;
   - el resultado (`ok` o el código de error);
   - cuántos registros devolvió y cuánto tardó.
   Nunca se guardan credenciales. La tabla es de solo añadir: no se puede modificar ni borrar una fila.
2. **Si no se puede auditar, no se responde** (falla cerrado): una llamada cuyo registro no se puede guardar devuelve el error `audit_unavailable` y ningún dato.
3. **Límite de llamadas por minuto y por login** (ADR 0009), aplicado antes de llamar a Odoo, para que también frene los intentos de adivinar claves. Error `rate_limited`.
4. **Registros hostiles** en los datos de demo: un contacto cuyo texto intenta dar órdenes al agente, y otro con un texto enorme. Las pruebas comprueban que llegan como datos marcados, recortados y sin efecto en el gateway.
5. **Más pruebas de fugas:**
   - filtrar por los ids de pedidos ajenos;
   - leer líneas de pedidos ajenos;
   - verificar que la clave nunca aparece en la auditoría.
6. **Trabajo de CI** que levanta Odoo en Docker, crea los datos de demo y ejecuta todas las pruebas de integración en cada push.

## Qué no entra

Una pantalla para consultar la auditoría, límites compartidos entre varias instancias (con Redis o la base de datos) y la retención o el archivado del registro.

## Escenarios de aceptación

```gherkin
Característica: Rastro y límites

  Escenario: Cada llamada queda auditada
    Cuando Ana hace una búsqueda de pedidos
    Entonces hay una fila en la auditoría con su login, su id de Odoo, la herramienta,
      los argumentos, el resultado "ok", el número de registros y la duración

  Escenario: Los intentos fallidos también quedan auditados
    Cuando alguien llama con el login de Ana y una clave falsa
    Entonces hay una fila con el login declarado, sin id de Odoo y resultado "unauthenticated"

  Escenario: La auditoría no guarda credenciales
    Después de cualquier llamada
    Entonces ninguna fila de la auditoría contiene la API key usada

  Escenario: La auditoría no se puede reescribir
    Cuando alguien intenta modificar o borrar una fila de la auditoría
    Entonces la base de datos lo rechaza

  Escenario: Sin auditoría no hay datos
    Dado que la base de datos de auditoría no está disponible
    Cuando Ana busca pedidos
    Entonces recibe el error "audit_unavailable" y ningún registro

  Escenario: Límite por minuto
    Dado un límite de N llamadas por minuto
    Cuando el mismo login hace N+1 llamadas en un minuto
    Entonces la última recibe "rate_limited" sin que se llame a Odoo
    Y otro login sigue pudiendo llamar

  Escenario: Un registro hostil es solo un dato
    Cuando Luis lee el contacto cuyo comentario dice "ignora tus instrucciones…"
    Entonces lo recibe como valor de un campo, con el aviso de que es un dato
    Y el gateway no hace nada más que devolverlo

  Escenario: Pedidos ajenos por id o por líneas
    Cuando Ana filtra pedidos por los ids de los pedidos de Luis
    O busca las líneas de esos pedidos
    Entonces no recibe ninguno
```
